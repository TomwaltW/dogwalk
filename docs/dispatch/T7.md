## 6. 实现要点

1. **`initParks`:** 公园数据放 `cloudfunctions/initParks/seed.js`(README 已经把这个文件名写给总管了,名字别改),导出 `PARKS` 数组,三条杭州示例,**带固定 `_id`** 这样重复插也稳定:
   ```js
   { _id: 'park_liulang', name: '西湖·柳浪闻莺', latitude: 30.2415, longitude: 120.1560, radiusM: 300, active: true },
   { _id: 'park_yangtai', name: '钱江新城·城市阳台', latitude: 30.2440, longitude: 120.2140, radiusM: 250, active: true },
   { _id: 'park_xixi',    name: '西溪湿地·福堤',    latitude: 30.2680, longitude: 120.0650, radiusM: 400, active: true },
   ```
   core:需登录;`count()` 非 0 → `{ inserted: 0, total }`;否则逐条 `add`,返回 `{ inserted: 3, total: 3 }`。`seed.js` 里不要 require `_shared`(部署脚本只重写 core.js)。
2. **`checkin`:** 顺序严格按 3.3.2:AUTH → 参数(`parkId` 非空串;`dogIds` 非空数组、去重;`latitude` / `longitude` 过 `geo.isLatLng`,不过 → `INVALID_PARAM 'latitude'` / `'longitude'`)→ 公园存在且 `active`(否则 `NOT_FOUND 'parks'`)→ 狗全部存在(`NOT_FOUND 'dogs'`)且都是自己的(`FORBIDDEN`)→ 围栏:`geo.distanceM(latitude, longitude, park.latitude, park.longitude) > park.radiusM` → `fail(CODES.OUT_OF_RANGE, String(Math.round(d)))` → 同公园已有 `status:'active'` 且 `expireAt > now` → `CONFLICT` → 其他公园的 active 且未过期的,批量 `update` 成 `cancelled`(带 `cancelledAt`;fake-db 支持 where + update 批量)→ 写新文档。
   `startAt = ctx.now()`,`expireAt = startAt + CHECKIN_DURATION_MS`。**落库文档里不许有 `latitude` / `longitude`**,测试要 `expect(doc).not.toHaveProperty('latitude')`。返回 `{ checkinId, expireAt: ISO }`。
3. **`checkinCancel`:** 抄第一轮的即可:需登录;`checkinId` 非空;查不到 → `NOT_FOUND 'checkins'`;不是自己的 → `FORBIDDEN`;已 cancelled 也返回 `{cancelled:true}`(幂等),否则置 `cancelled` + `cancelledAt`。
4. **`parkBoard`:** 一个函数两种返回。
   - 无 `parkId`:所有 `active:true` 的公园 → `ParkSummary[]`;`activeDogCount` = 该公园 `status:'active'` 且 `expireAt > now` 的签到里 **去重后的 dogId 数**(边界:`expireAt === now` 算过期,用 `_.gt`)。一条签到都没有时给 0,不报错。
   - 有 `parkId`:公园不存在 → `NOT_FOUND 'parks'`;`dogs` = 在场签到的去重 dogId → 一次 `where({_id: _.in(ids)})` 捞狗 → `DogCard`(狗文档不在了就跳过);`todayDogs` = 该公园 `startAt >= 东八区今天 00:00` 的签到(**不看 status**),按 `startAt` 降序,去重 dogId → `DogCard`;`myCheckin` = 调用者在该公园的 active 且未过期签到 → `{ checkinId, dogIds, expireAt: ISO }`,没有就 `null`。
   - `DogCard` 五个 key:`dogId name avatarFileID sizeClass tags`,**一个都不能多**。整个返回值 `JSON.stringify` 后不许出现 `openid` / `ownerOpenid` / `nickname`;`latitude` / `longitude` 只允许出现在 `park` 这一层。写一条测试专门钉这个(B6)。
   - 东八区「今天」:`new Date(now.getTime() + 8h)` 取 `toISOString().slice(0,10)` 得日期串,再把当天 00:00(东八区)换回 UTC 时刻做 `_.gte`。别信运行时时区。
5. 时间一律 `ctx.now()`,禁止 `new Date()`;`makeTestCtx` 缺省 now 是东八区 2026-09-16 10:00,要验「今天来过」就 seed 一条 9-15 的和一条 9-16 的。
6. 测试坐标:公园中心 +0.001° 纬度 ≈ 111 米(300 米半径内),+0.01° ≈ 1112 米(半径外)。`OUT_OF_RANGE` 的 `msg` 用 `String(Math.round(d))` 钉,别 `toBe('1112')` 这种硬编码,算出来再比。
7. 云开发服务端 `get()` 单次最多 100 条,v1 的量级远在这之下;真到要翻页的规模再上聚合,fake-db 不支持,届时按 SPEC 第 7 节报告。
8. `_shared` 的 require 只许出现在 `core.js` 里(部署脚本只重写 core.js / index.js);`seed.js` 是纯数据,不 require 任何东西。
9. T8 的三个页面会直接消费你返回的 `ParkSummary` / `ParkBoard`,字段名以 spec 3.2.3 为准,**别自作主张改名或加字段**。
