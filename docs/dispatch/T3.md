## 6. 实现要点

1. **`ownerContact` 的来源在契约里不存在 —— 把接缝留好,不要自己补来源。**
   3.2 的 `DogPublic` 要求 `ownerContact: String | null`,B5 要求 `lostMode:true` 时它非 null。
   但 3.2 的 `users` 和 `dogs` 两张字段表里**没有任何可以当联系方式的字段**,SPEC 第 1 节还写明
   「不做实名认证、不做手机号获取」。总管已经知道,补契约是他的事,不是你的。你要做的是:
   - 在 `cloudfunctions/scanTag/core.js` 里单独写一个 `resolveOwnerContact(dog, owner)`,
     函数体现在就 `return null;`,上面留一行注释写明「来源字段待定,见 SPEC 3.2 DogPublic」。
   - 对外返回值写成 `ownerContact: dog.lostMode ? resolveOwnerContact(dog, owner) : null`。
     **门控逻辑现在就要写对、并且测到**;将来总管补完字段,只改 `resolveOwnerContact` 一个函数体。
   - `tests/cloud/scanTag.test.js` 里为走失态的取值挂一条
     `test.todo('lostMode 时 ownerContact 的取值 —— 等契约补来源字段')`。
     `test.todo` 不算失败,`npm test` 照样退出码 0,但每次跑都会把这个洞显示出来。
   - **不要**往 `users` / `dogs` 加字段,**不要**拿 `nickname` 顶替,**不要**把这条 todo 删掉刷绿。
2. 非走失态的口径要同时满足两处:2.2 B5 说「**不含** `ownerContact`」,3.2 说「否则**必须为 null**」。
   两边都满足的写法是 **key 存在、值为 `null`**,断言写 `toBeNull()`。
3. `scanTag` 是 `AUTH_REQUIRED` 的**唯一例外**,允许游客(`ctx.openid === ''`)调用(3.4)。
   scanLogs 的 `scannerOpenid` 在游客态写 `''`(3.2),不是 null、不是 undefined。
4. `DogPublic` **字段只能少不能多**(3.2)。别把 `_id`、`ownerOpenid`、`tagCode`、`socialOk`、

5. `tagCode`:长度取 `require('../_shared/contracts')` 的 `TAG_CODE_LENGTH`(=6),不要写字面量;
   字符集 `[a-z0-9]`;全局唯一;**已生成过就复用已有的,不新建**(6 节 T3)。
   云函数里可以用 `Math.random()` 生成(3.3.4 那条禁令只约束页面),但测试要能确定性地验证长度和复用。

   另外 fake-db **不支持聚合和事务**(3.3.5),`dailyJob` 的 encounters 统计只能 `where()` + `get()` 自己算。
