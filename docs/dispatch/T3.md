## 6. 实现要点

1. **契约缺口 —— 开工前等总管确认,不要自己发明。**
   3.2 的 `DogPublic` 要求返回 `ownerContact: String | null`,B5 要求 `lostMode:true` 时它非 null。
   但 3.2 的 `users` 和 `dogs` 两张字段表里**没有任何可以当联系方式的字段**,SPEC 第 1 节还写明
   「不做实名认证、不做手机号获取」。也就是说 `ownerContact` 的数据来源在契约里不存在。
   这正是 SPEC 第 7 节第 1 条的情形:「需要的接口在契约里找不到 → **停,报告**。不要自己发明一个。」
   **不要往 `users` 或 `dogs` 里加字段,也不要拿 `nickname` 顶替。** 在回执里报告这一条,
   等总管补完契约再做 B5 的 `lostMode` 分支;`lostMode:false` 分支和 scanLogs 写入可以先做。
2. `ownerContact` 的两处口径要取交集:2.2 B5 说非走失时「**不含** `ownerContact`」,3.2 说
   「否则**必须为 null**」。两边都满足的写法是 **key 存在、值为 `null`**,断言写 `toBeNull()`。
3. `scanTag` 是 `AUTH_REQUIRED` 的**唯一例外**,允许游客(`ctx.openid === ''`)调用(3.4)。
   scanLogs 的 `scannerOpenid` 在游客态写 `''`(3.2),不是 null、不是 undefined。
4. `DogPublic` **字段只能少不能多**(3.2)。别把 `_id`、`ownerOpenid`、`tagCode`、`socialOk`、
   `qrFileID`、`createdAt` 漏出去 —— 照 3.2 那段列的字段逐个挑,多一个就算越界。
5. `tagCode`:长度取 `require('../_shared/contracts')` 的 `TAG_CODE_LENGTH`(=6),不要写字面量;
   字符集 `[a-z0-9]`;全局唯一;**已生成过就复用已有的,不新建**(6 节 T3)。
   云函数里可以用 `Math.random()` 生成(3.3.4 那条禁令只约束页面),但测试要能确定性地验证长度和复用。
6. `deduct()` 对**不存在**的 templateKey 要当 0 处理:返回 `false` 且**不抛错**(6 节 T3)。
   另外 fake-db **不支持聚合和事务**(3.3.5),`dailyJob` 的 encounters 统计只能 `where()` + `get()` 自己算。
