## 6. 实现要点

1. **先跑一遍旧测试再动手。** 你接手的 `login` / `dogCRUD` / `genTagCode` / `scanTag` 及其测试此刻是绿的,但它们按的是第一轮契约(`playStyle` / `temperament` / `okWithSmallDogs` / `socialOk` / `ownerContact`)。你的活是把实现和测试**一起**改到 v2,不是在旧测试上打补丁。旧测试怎么组 ctx、怎么断言的写法可以照抄,但改用 `makeTestCtx`(`tests/fakes/cloud-ctx.js`),它一把给你 `ctx.security` / `ctx.storage` / `calls`。
2. **`dogCRUD`:** 客户端可写字段只有 3.3.2 列的 12 个。校验顺序:归属 → 字段合法 → 内容安全,任何一步不过都不写库。
   - `name` 1-12 **按码位数**(`Array.from(s).length`,不是 `.length`);`breed` ≤ 20;`licenseNo` ≤ 32;`lostNote` ≤ 50;`tags` 是 `TAGS` 子集且去重;`neutered` / `vaccinated` / `lostMode` 是 Boolean;`birthMonth` `''` 或 `YYYY-MM`。create 的必填还是 `name` / `sizeClass` / `gender`,其余给默认(`vaccinated:false`、`licenseNo:''`、`tags:[]`、`lostNote:''`、`lostMode:false`)。
   - 内容安全:`name` / `breed` / `licenseNo` / `lostNote` 里**这次给了的**字段逐个 `await ctx.security.checkText()`,false → `fail(CODES.CONTENT_RISKY, '<字段名>')`;`avatarFileID` 给了、非空、且和库里现有的不同 → `checkImage`,false → `fail(CONTENT_RISKY, 'avatarFileID')`。
   - 把 `PLAY_STYLE` / `TEMPERAMENT` 的 require 删掉(它们是过渡期常量,你改完之后全仓就不该再有人引用)。
3. **`login`:** 新建 users 文档不再有 `followSpotIds`,加 `subTemplates: {}`;其余不变。二次调用不覆盖 `subQuota` / `subTemplates`。
4. **`scanTag`:** 返回值改成 3.2.3 的 `DogPublic`,**恰好 9 个 key**;`lostNote` 只在 `lostMode:true` 时给,否则 `''`。删掉 `resolveOwnerContact`、删掉读 users 那段(不再需要主人任何信息)。把那条 `test.todo` 换成真用例(比如「走失态带 lostNote,非走失态 lostNote 为空串」)。scanLogs 照写。
5. **`genTagCode`:** `wxacode.getUnlimited` 返回 `{ buffer, contentType }`,拿 `buffer` 调 `ctx.storage.uploadFile('tags/' + tagCode + '.png', buffer)`,返回值就是 `qrFileID`。openapi 抛错或没带 buffer → `logger.error`、`qrFileID` 留 `''`、主流程仍 ok(3.4)。`page` 参数固定 `'pages/dog/profile/profile'`,`checkPath:false`。已有 tagCode / qrFileID 的复用,不重摇不重传。
6. **`reportFound`(新):** 允许游客。校验:`tagCode` 六位 `[a-z0-9]`;`message` 1-200;`latitude` / `longitude` 要么都不给,要么都给且过 `_shared/geo.isLatLng`。`checkText(message)` false → `CONTENT_RISKY`。按 tagCode 找狗,没有 → `NOT_FOUND 'dogs'`。落库形状见 3.2.2 `found_reports`(没给坐标就是 `null`,`reporterOpenid` 游客是 `''`)。
   通知:读 `users.doc(dog.ownerOpenid)`(拿不到就当没额度);`subQuota[TEMPLATE_KEYS.FOUND_REPORT] > 0` 且 `subTemplates[TEMPLATE_KEYS.FOUND_REPORT]` 非空才发。文件顶部放一个常量给总管改字段名用:
   ```js
   const TEMPLATE_FIELDS = { name: 'thing1', message: 'thing2', time: 'time3' };
   ```
   `send({ touser, template_id, page: 'pages/dog/tag/tag?dogId=' + dog._id, data: { [TEMPLATE_FIELDS.name]: {value: 狗名}, [TEMPLATE_FIELDS.message]: {value: 留言前 20 字}, [TEMPLATE_FIELDS.time]: {value: 'YYYY-MM-DD HH:mm'(东八区)} } })`。
   发成功:`subQuota.<key>` 用 `ctx._.inc(-1)` 扣 1,报告文档 `notified:true`,返回 `notified:true`。发失败(抛错):`logger.error`,不扣,`notified:false`,主流程仍 ok。额度为 0 / 没记模板:不调 send,`notified:false`,**不报错**。
7. **`foundReports`(新):** 需登录;`dogId` 必填;狗不存在 → `NOT_FOUND`;`dog.ownerOpenid !== ctx.openid` → `FORBIDDEN`;`where({dogId}).orderBy('createdAt','desc').limit(50)`,映射成 `FoundReport`(`createdAt` 转 ISO,坐标缺省 `null`)。
