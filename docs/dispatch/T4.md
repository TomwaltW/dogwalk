## 6. 实现要点

1. **SPEC 3.3.3 里那句 `jest.mock('../../api/index')` 是从页面文件视角写的,照抄进 `tests/pages/*.test.js` 会报 `Cannot find module`(已实测)。** 测试文件里正确写法是:
   ```js
   jest.mock('../../miniprogram/api/index');
   const api = require('../../miniprogram/api/index');
   ```
   页面文件里则照常写 `require('../../api/index')`。
2. 页面模块必须按 3.3.4 收尾:`Page(options); module.exports = options;`。**少了 `module.exports`,`loadPage()` 就拿不到页面对象**,你的测试会直接跑不起来。
3. 用 `tests/fakes/mini-runtime.js` 的 `loadPage('miniprogram/pages/index/index.js')` 加载页面。返回对象上已经挂了会真实写 `data` 的 `setData`,断言直接读 `page.data`;注入的 wx 在 `page.__wx`,调用记录在 `page.__wx.__calls`(形如 `[{name:'navigateTo', opts:{...}}]`)。
4. 页面**禁止**直接调 `wx.cloud.callFunction`,一律走 `require('../../api/index')`(3.3.3)。页面里也不许出现 `new Date()`(3.3.4)。
5. 捕获 `ApiError` → 设 `data.errMsg`,**不得抛出、不得白屏**(3.4)。B6 明确要求 api 抛错时 `onLoad` 自身不抛异常 —— 测试里 `await expect(page.onLoad.call(page, {})).resolves.not.toThrow()` 这类断言要真做。
6. checkin 页未选狗时必须在**页面本地**拦下:`data.errMsg` 非空 **且 api 一次都没被调用**(6 节 T4)。用 `expect(api.createCheckin).not.toHaveBeenCalled()` 断言后半句 —— 这半句最容易漏。
