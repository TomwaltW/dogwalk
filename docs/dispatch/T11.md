## 6. 实现要点

1. **组织:** `core.js` 里 `ACTIONS = { create, list, get, join, decide, leave, cancel, message }`,`action` 不在表里 → `INVALID_PARAM 'action'`;所有 action 需登录;每个 action 一个函数,公共部分(捞狗转 DogCard、捞公园名、算 myStatus、算 dogCount)抽成本文件内的 helper。core 可以拆成 `core.js` + 同目录其他文件,但 **`_shared` 的 require 只许出现在 `core.js`**(部署脚本只重写 core.js / index.js),其他文件通过参数拿 `COLL` / `CODES`。
2. **`toDogCard(dog)`** 恰好五个 key:`dogId name avatarFileID sizeClass tags`(`tags` 缺省 `[]`)。狗文档不在了(被删)就跳过。所有对外的狗都必须过这个函数,**任何地方不许把 dog 文档原样返回**。
3. **`create`:** 校验 `parkId`(公园存在且 `active`,否则 `NOT_FOUND 'parks'`)、`startAt`(可解析且 `> ctx.now()`,否则 `INVALID_PARAM 'startAt'`)、`dogIds`(非空、去重、全是自己的:`NOT_FOUND 'dogs'` / `FORBIDDEN`)、`note`(≤ `LIMITS.WALK_NOTE_MAX`,缺省 `''`)、`maxDogs`(整数 1..`WALK_MAX_DOGS_CAP`,缺省 `WALK_MAX_DOGS_DEFAULT`,且 `>= dogIds.length` 否则 `INVALID_PARAM 'maxDogs'`)。`checkText(note)` false → `CONTENT_RISKY 'note'`。落库后返回 `WalkSummary`(`isHost:true`、`myStatus:'host'`、`dogCount = dogIds.length`)。
4. **`list`:**
   - `mine` 不为 true:`status:'open'` 且 `startAt > now`;带 `parkId` 就加条件;带 `date`(`YYYY-MM-DD`,格式不对 → `INVALID_PARAM 'date'`)就过滤 `startAt` 落在东八区那一天内的;按 `startAt` 升序。
   - `mine` 为 true:我是 host 的 + 我在 `walk_members` 里 `status ∈ {pending, approved}` 的,`startAt > now - 7 天`,**含 cancelled**,按 `startAt` 降序,去重。
   - 每条转 `WalkSummary`:`parkName` 从 parks 捞(公园没了给 `''`);`hostDogs` 是 host 狗的 DogCard;`dogCount` = host 狗数 + 该 walk 下 `approved` 成员的狗数之和;`isHost` / `myStatus` 按调用者算(`myStatus` 优先级:host > 该用户在 members 里那条的 status > `'none'`)。
   - 东八区日期:`new Date(t.getTime() + 8h).toISOString().slice(0,10)`,别信运行时时区。
5. **`get`:** walk 不存在 → `NOT_FOUND 'walks'`。`members`:host 看全部状态;其他人只看 `approved` + 自己那条(任何状态)。`messages`:`myStatus ∈ {host, approved}` 才给,按 `createdAt` 升序,否则 `[]`;每条 `dogName` = 发言者 `dogId` 对应狗的名字(狗没了给 `'某只狗'`),`isMe` 按 openid。`myDogs` = 调用者自己的狗的 DogCard(按 `createdAt` 升序)。`walk` 是 `WalkSummary`(含 `status`)。
6. **`join`:** walk 不存在 → `NOT_FOUND`;`status !== 'open'` 或 `startAt <= now` → `CONFLICT 'walk closed'`;host 自己 → `FORBIDDEN`;`dogIds` 非空、去重、都是自己的。已有 members 记录:`pending` / `approved` / `rejected` → `CONFLICT '<状态>'`;`left` → 把那条改回 `pending`(更新 `dogIds` / `updatedAt`);没有 → 新建 `pending`。返回 `{ memberId, status: 'pending' }`。**申请时不查容量**,容量在 decide 时查(假设 6:满了也让人排队,由 host 决定)。
7. **`decide`:** member 不存在 → `NOT_FOUND 'walk_members'`;对应 walk 的 host 不是我 → `FORBIDDEN`;member 不是 `pending` → `CONFLICT`;walk 已 cancelled → `CONFLICT`。`approve:true` 时:host 狗数 + 已 `approved` 成员狗数 + 这条的狗数 `> maxDogs` → `WALK_FULL`(不改状态);否则置 `approved`。`approve:false` → `rejected`。返回 `{ memberId, status }`。
8. **`leave`:** host → `FORBIDDEN`(只能 cancel);没有我的 member 记录或已是 `rejected` / `left` → `CONFLICT`;否则置 `left`。返回 `{ left: true }`。
9. **`cancel`:** 只有 host(`FORBIDDEN`);已 cancelled 也返回 `{ cancelled: true }`(幂等);否则置 `cancelled` + `updatedAt`。
10. **`message`:** walk 不存在 → `NOT_FOUND`;已 cancelled → `CONFLICT`;`myStatus ∉ {host, approved}` → `FORBIDDEN`;`text` 去空白后 1..`LIMITS.MESSAGE_MAX`,否则 `INVALID_PARAM 'text'`;`checkText` false → `CONTENT_RISKY 'text'`。`dogId` = host 用 `walk.dogIds[0]`,成员用自己 member 记录的 `dogIds[0]`。返回 `{ messageId }`。
11. 时间一律 `ctx.now()`,禁止 `new Date()`;所有对外的时间字段转 ISO 串。`makeTestCtx` 缺省 now 是东八区 2026-09-16 10:00,测 `list` 的 date 过滤和 7 天窗口就围绕它 seed。
12. **测试要钉形状:** 对 `create` / `list[0]` / `get` 的返回分别 `expect(Object.keys(x).sort()).toEqual([...])`,key 列表照 3.2.3 抄;`get.members[0]` / `get.messages[0]` / `hostDogs[0]` 同样钉。整个 `get` 返回值 `JSON.stringify` 后不含 `openid` / `hostOpenid` / `nickname`(写一条专门的用例)。
13. T10 的三个页面按 spec 3.2.3 的形状 mock 你的返回,**别自作主张改名或加字段**;发现契约缺什么(比如页面需要但 spec 没给的字段)→ 停下来报告,不要偷偷加。
