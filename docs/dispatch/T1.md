## 6. 实现要点

1. **`_shared/schema.js` 的 `validateDog` / `validateProfile` 现在全是 `throw new Error('NOT_IMPLEMENTED')`,而且属 T0 只读 —— 不要调用它。** 云端校验写在你自己的 `cloudfunctions/dogCRUD/core.js` 里,枚举值 `require('../_shared/contracts')` 取 `SIZE_CLASS`,失败按 3.4 返回 `fail(CODES.INVALID_PARAM, '<字段名>')`。
2. `tests/logic/dog.test.js` 测的是 `miniprogram/logic/dog.js`(前端本地校验),跟 `_shared/schema.js` 是两个东西。6 节 T1 行里说的 `validateDog` 指前者,由你在 `miniprogram/logic/dog.js` 里定义并导出。
3. `users` 的 `_id` 就是 `_openid`(3.2)。注意 fake-db 的 `doc(id).get()` 在文档不存在时是 **reject** 而不是 resolve(null) —— 判存在要 try/catch,或改用 `where({_openid}).get()` 看 `data.length`。
4. 时间一律取 `ctx.now()`,禁止 `new Date()`(3.3.1)。测试里用 `tests/fakes/clock.js` 的 `fixedClock('2026-09-14T19:30:00+08:00')` 注进 `ctx.now`。
5. `dogCRUD` 的五个 action(`create`/`update`/`get`/`listMine`/`remove`)都要实现;`update`/`remove`/`get` 前先比 `ownerOpenid !== ctx.openid` → `fail(CODES.FORBIDDEN)`(3.4)。
6. core **永远不抛异常给调用方**,一律 `return fail(...)`(3.1)。`index.js` 外层虽有兜底 try/catch,但不要指望它兜业务错误。
