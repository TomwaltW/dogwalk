## 1. 问题定义

**要做什么**(一句话):
一个帮助狗主人线下社交的微信小程序:给狗建档、生成可打印的身份牌(小程序码)、到公园签到后互相看得见、发起约遛并在详情页交流;狗走丢时路人扫牌能留言,主人收到订阅消息。

**技术栈(不要更换)**:原生微信小程序(WXML / WXSS / JS)+ 微信云开发 CloudBase(云函数 + 云数据库 + 云存储)+ 小程序原生 `<map>`;身份直接用云函数里的 OPENID;JavaScript + JSDoc + ESLint,注释中文。

**明确不做**(写出来防止执行者顺手扩张):

- 不做 App、不做支付 / 商城 / 代遛 / 寄养、不做手机号登录、不做实名。
- 不做站内私信 / IM。唯一的文字交流是约遛详情页的留言区(成员可见)。
- 不做「附近的狗」、不做距离排序、不做用户自建公园。公园由 `initParks` 云函数写死 3 条示例。
- 不记录、不展示用户精确坐标。签到坐标只在云函数里做一次围栏校验,**校验完不落库**。地图页 / 公园页只展示狗,不展示主人昵称、头像、openid。
- 不做 TypeScript、不做 CI(GitHub Actions 等),本地 `npm test` 即可。
- **不做真机 UI 验收。** WXML 渲染效果、真机交互、云环境联调、订阅消息真发、`<map>` 真渲染一律不在本轮验收范围内,由总管在 TΩ2 之后人工回归。执行者不要尝试,也不要因为「没法验证界面好不好看」而停下。

## 3. 冻结契约

以下定义在本轮内不可更改。任何任务需要改动 = 停下来报告,不要自己改。

### 3.1 统一返回形状与错误码

所有云函数 `core` 的返回值只有两种形状:

```js
{ ok: true,  data: <any> }
{ ok: false, code: <ErrorCode>, msg: <string> }
```

```js
// cloudfunctions/_shared/errors.js
const CODES = {
  AUTH_REQUIRED:   'AUTH_REQUIRED',   // 无 openid
  INVALID_PARAM:   'INVALID_PARAM',   // 参数校验失败,msg = 字段名
  NOT_FOUND:       'NOT_FOUND',       // 资源不存在,msg = 集合名
  FORBIDDEN:       'FORBIDDEN',       // 非本人资源 / 无权操作
  CONFLICT:        'CONFLICT',        // 状态冲突(重复签到、重复申请)
  OUT_OF_RANGE:    'OUT_OF_RANGE',    // 签到不在公园半径内,msg = 距离(米,整数字符串)
  CONTENT_RISKY:   'CONTENT_RISKY',   // 内容安全不通过,msg = 字段名
  WALK_FULL:       'WALK_FULL',       // 约遛满员
  QUOTA_EXHAUSTED: 'QUOTA_EXHAUSTED', // 订阅消息额度不足(预留,本轮无人返回它)
  INTERNAL:        'INTERNAL',        // 兜底
};
function fail(code, msg) { return { ok: false, code, msg: msg || code }; }
function ok(data)        { return { ok: true, data: data === undefined ? null : data }; }
```

云函数**永远不抛异常给调用方**,一律返回 `fail(...)`。`_shared/runtime.js` 的 handler 外层 try/catch 兜底成 `fail(INTERNAL, e.message)`。

### 3.3 调用面

#### 3.3.1 云函数 core 签名与 ctx

```js
// cloudfunctions/<name>/core.js
/**
 * @param {object} event                云函数入参
 * @param {object} ctx
 * @param {object} ctx.db               云开发 db 实例(测试时为 fake-db)
 * @param {object} ctx._                db.command
 * @param {string} ctx.openid           调用者 openid,游客为 ''
 * @param {() => Date} ctx.now          取当前时间,禁止直接 new Date()
 * @param {object} ctx.openapi          cloud.openapi,测试时为 mock
 * @param {{info:Function,error:Function}} ctx.logger
 * @param {object} ctx.storage          云存储句柄(本轮新增)
 * @param {(fileID:string)=>Promise<Buffer>} ctx.storage.downloadFile
 * @param {(cloudPath:string, buffer:Buffer)=>Promise<string>} ctx.storage.uploadFile   // 返回 fileID
 * @param {object} ctx.security         内容安全(本轮新增;true = 通过)
 * @param {(text:string)=>Promise<boolean>} ctx.security.checkText     // 空串 / 纯空白直接 true
 * @param {(fileID:string)=>Promise<boolean>} ctx.security.checkImage  // '' 直接 true
 * @returns {Promise<{ok:true,data:any}|{ok:false,code:string,msg:string}>}
 */
module.exports = async function core(event, ctx) {};
```

`index.js` 固定长这样(每个云函数一样,一行都不用改):

```js
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const core = require('./core');
const { handler } = require('../_shared/runtime');

exports.main = handler(cloud, core);
```

`_shared/runtime.js` 负责组 ctx(db / openid / now / openapi / logger / storage / security)并兜底异常;`_shared/security.js` 负责调 `security.msgSecCheck`(v2)与 `security.imgSecCheck`。
**口径**:接口明确返回 risky / review → false;接口调用本身失败(网络、额度、未开通)→ `logger.error` 后返回 **true**(放行)。这是总管定的取舍:内容安全接口挂了不能让整个 app 不能建档。

`_shared` 在部署时由 `scripts/deploy-shared.js` 复制进每个云函数目录,并把 `core.js` / `index.js` 里的 `require('../_shared/x')` 重写为 `'./_shared/x'`。**仓库源码里一律写 `'../_shared/x'`**,且 `_shared` 的 require 只能出现在 `core.js` 与 `index.js` 两个文件里(脚本只重写这两个)。

### 3.4 失败面

| 场景 | 行为 |
|---|---|
| `ctx.openid === ''` 且接口需要登录 | `fail(AUTH_REQUIRED)`。例外:`scanTag`、`reportFound` 允许游客 |

| 资源不属于调用者 / 非 host 做 host 的事 | `fail(FORBIDDEN)` |

| 订阅额度为 0 或没记过模板 id | **不报错**,`notified:false` |
| 订阅消息 / 小程序码 / 内容安全等 openapi 调用抛错 | 记 `logger.error`,**不影响主流程返回 ok**(内容安全按 3.3.1 放行) |
| 前端 api 层收到 `ok:false` | reject `new ApiError(code, msg)` |
| 页面捕获 ApiError | 设置 `data.errMsg`,**不得抛出**,不得白屏 |

## 7. 卡住了怎么办

1. 需要的接口 / 字段在契约里找不到 → **停,报告**。不要自己发明一个。
2. 需要改的文件不在自己的白名单里 → **停,报告**。不要「就改一行」。

4. 验收命令本身跑不起来(环境问题) → 先自己排查,排查不动 → 报告。

报告 = 在回执里写清楚卡在哪、试过什么、需要什么决定,然后结束这一轮,不要继续硬做。

1. 「年龄或生日」只存 `birthMonth`('YYYY-MM'),年龄由前端算;不单独存年龄数字。

5. 「今天来过」按东八区自然日算,含已签退的。
6. 约遛人数上限 `maxDogs` 按**狗**数算(需求原话「人数上限（默认 3 只狗）」),发起人的狗计入。
7. 被拒绝的申请不能再申请同一场;退出的可以再申请。
8. 留言区只对发起人和已批准成员开放;留言以「狗名」署名,不显示主人昵称。
9. 内容安全接口本身调用失败时放行并记 error 日志(接口明确判 risky / review 才拒绝)。

## 11. 变更记录(本轮验收通过之后的改动)

第二轮 T6-T11 / TΩ2 全部验收通过、合进 main 之后发生的改动记在这里。
上面第 1-10 节仍按冻结时的原文保留,只有 3.2.2 的 `users` 表加了一行并标了出处。

### 2026-09-17 —— 跨端身份:users 加 `unionid`

**为什么**:总管决定以后要出 App 版(iOS + Android),要求与小程序**同一批用户、同一份数据**。
`OPENID` 只在微信里有,独立 App 拿不到;两端认同一个人靠的是微信开放平台的 `UNIONID`
(小程序与 App 绑在同一个开放平台账号下,同一微信用户的 UNIONID 相同)。

**怎么改的**(改动极小,因为身份来源本来就收敛在一处):

- `_shared/runtime.js` 的 `handler` 从 `getWXContext()` 多取一个 `UNIONID`,经 `makeCtx` 暴露成 `ctx.unionid`
- `login/core.js` 建档时存 `unionid`;老用户再登录时若库里的值与本次不同就补录
- 其余 11 个云函数**一行未改** —— 它们认人一律走 `ctx.openid`

**关键决定:主键仍是 `openid`,不是 `unionid`。**
开放平台认证要钱要时间,绑定发生在哪一天不确定。主键若随「这次有没有 UNIONID」而变,
绑定前注册的人和绑定后回来的同一个人会被认成两个账号,狗和约遛全丢。
所以 `unionid` **只记录、不夺权**:绑定前是空串,绑定后老用户下次登录自动补上,
**不需要任何数据迁移**。

**App 接入时的用法**:App 侧用微信登录拿到 unionid → 查 `users` 里 `unionid` 相同的那条
→ 取它的 `_id`(即 openid)当身份往下走,现有云函数一行不用改。

**对本轮验收的影响**:`tests/cloud/login.test.js` 的整键集断言加了 `unionid` 一项;
新增 5 条 login 用例 + 2 条 runtime 用例覆盖上述行为。全量 535 passed。

**仍待总管做的事**(补进第 8 节):注册微信开放平台账号,把小程序绑上去。
绑之前一切照常跑,只是 `unionid` 一直是空串。
