## 1. 问题定义

**要做什么**(一句话):
一个微信小程序 + 云开发后端,让同一个小区的狗主在固定的几个遛狗点位上「彼此看得见」——有人点「我出门了」,关注同点位的人收到通知;每只狗有一张挂在项圈上的二维码牌,扫一下能看到狗档案,走失时能联系主人。

**为什么要做**:
遛狗人群本来每天都会在固定时间出现在固定地点,产品不需要「组局协调」,只需要「让在场的人互相可见」。因此失败成本为零(没人用也不影响用户遛狗),核心循环极短。v1 的唯一目标是在**一个小区**里验证:有人会点「出门了」,并且有人会因此出门。

**明确不做**(写出来防止执行者顺手扩张):

- 不做任何站内聊天 / IM / 私信。聊天全部外包给微信群,点位详情页只展示一张群二维码图片。
- 不做地图、不做「附近」、不做距离排序、不调 `wx.getLocation`。点位是运营在数据库里手工录入的固定条目,用户手动选。
- 不做实名认证、不做手机号获取、不做支付。
- 不做互助寄养 / 时间币(那是 v2)。
- 不做用户自建点位。
- 不做 TypeScript。全部 JavaScript + JSDoc + ESLint。
- 不做真机 UI 验收。WXML 渲染效果、真机交互、云环境联调一律不在本轮验收范围内,由总管在 TΩ 之后人工回归。执行者不要尝试,也不要因为「没法验证界面好不好看」而停下。
- 不做 CI(GitHub Actions 等)。本地 `npm test` 即可。

## 3. 冻结契约

以下定义在本轮内不可更改。任何任务需要改动 = 停下来报告,不要自己改。

### 3.1 统一返回形状与错误码

所有云函数 `core` 的返回值只有两种形状:

```js
{ ok: true,  data: <any> }
{ ok: false, code: <ErrorCode>, msg: <string> }
```

```js
// cloudfunctions/_shared/errors.js
const CODES = {
  AUTH_REQUIRED:    'AUTH_REQUIRED',    // 无 openid
  INVALID_PARAM:    'INVALID_PARAM',    // 参数校验失败
  NOT_FOUND:        'NOT_FOUND',        // 资源不存在
  FORBIDDEN:        'FORBIDDEN',        // 非本人资源
  CONFLICT:         'CONFLICT',         // 状态冲突(如重复广播)
  QUOTA_EXHAUSTED:  'QUOTA_EXHAUSTED',  // 订阅消息额度不足
  INTERNAL:         'INTERNAL',         // 兜底
};
function fail(code, msg) { return { ok: false, code, msg: msg || code }; }
function ok(data)        { return { ok: true, data: data === undefined ? null : data }; }
```

云函数**永远不抛异常给调用方**,一律返回 `fail(...)`。`index.js` 外层 try/catch 兜底成 `fail(INTERNAL, e.message)`。

### 3.3 调用面

#### 3.3.1 云函数 core 签名(所有云函数一致)

```js
// cloudfunctions/<name>/core.js
/**
 * @param {object} event                云函数入参
 * @param {object} ctx
 * @param {object} ctx.db               云开发 db 实例(测试时为 fake-db)
 * @param {object} ctx._                db.command
 * @param {string} ctx.openid           调用者 openid,游客为 ''
 * @param {() => Date} ctx.now          取当前时间,禁止直接 new Date()
 * @param {object} ctx.openapi          cloud.openapi,测试时为 mock
 * @param {{info:Function,error:Function}} ctx.logger
 * @returns {Promise<{ok:true,data:any}|{ok:false,code:string,msg:string}>}
 */
module.exports = async function core(event, ctx) {};
```

`index.js` 固定长这样(每个云函数都一样,只改 require 的名字):

```js
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const core = require('./core');
const { fail, CODES } = require('./_shared/errors');

exports.main = async (event, context) => {
  const { OPENID } = cloud.getWXContext();
  const db = cloud.database();
  try {
    return await core(event, {
      db, _: db.command, openid: OPENID || '',
      now: () => new Date(), openapi: cloud.openapi, logger: console,
    });
  } catch (e) {
    console.error(e);
    return fail(CODES.INTERNAL, e.message);
  }
};
```

> `_shared` 在部署时由脚本复制进每个云函数目录。测试时 `core.js` 用相对路径 `require('../_shared/errors')`。**T0 负责把这个路径差异处理掉**(约定:`core.js` 一律写 `require('../_shared/errors')`,部署脚本负责重写)。

### 3.4 失败面

| 场景 | 行为 |
|---|---|
| `ctx.openid === ''` 且接口需要登录 | `fail(AUTH_REQUIRED)`。例外:`scanTag` 允许游客 |
| 必填字段缺失 / 枚举值非法 / 字符串超长 | `fail(INVALID_PARAM, '<字段名>')` |
| 按 id 查不到文档 | `fail(NOT_FOUND, '<集合名>')` |
| 操作的资源 `ownerOpenid !== ctx.openid` | `fail(FORBIDDEN)` |
| 同一 openid 在同一 spotId 已有 active 且未过期的 checkin | `fail(CONFLICT, 'active checkin exists')` |
| 订阅消息额度为 0 | **不报错**,正常返回,`data.notified` 计数不含该用户 |
| 发订阅消息 / 生成小程序码的 openapi 调用失败 | 记 `logger.error`,**不影响主流程返回 ok** |
| 前端 api 层收到 `ok:false` | reject `new ApiError(code, msg)` |
| 页面捕获 ApiError | 设置 `data.errMsg`,**不得抛出**,不得白屏 |

## 7. 卡住了怎么办

按顺序:

1. 需要的接口在契约里找不到 → **停,报告**。不要自己发明一个。
2. 需要改的文件不在自己的白名单里 → **停,报告**。不要「就改一行」。
3. fake-db 不支持你需要的查询能力(聚合、事务、地理) → **停,报告**。不要绕过 fake-db 直接连真实数据库,也不要自己在 tests 目录外再写一个 fake。
4. 验收命令本身跑不起来(环境问题) → 先自己排查,排查不动 → 报告。
5. 验收过不了但代码逻辑自认为对 → **以验收为准**,继续改;确信是验收标准写错了 → 停,报告。

报告 = 在回执里写清楚卡在哪、试过什么、需要什么决定,然后结束这一轮,不要继续硬做。
